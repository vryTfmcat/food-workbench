# 食物工作台 0.1.2

独立 Obsidian 插件（最低 1.13.0）：最近想吃 → 自由组合在家餐食／外出候选 → 主动选择意向日期。不是自动膳食计划。

## 使用

命令面板“食物工作台：打开食物工作台”或侧栏餐具图标。

- 左栏从券食里挑出的、全部券、口述家中食品、食品批次、做饭菜式、可购买食材和地点中挑选。
- 现有 `eventStatus: planned` 只作为“用户曾挑出”的线索；日期／时段不复制到工作卡，也不判断用餐冲突。已结束主档仍标明来源状态，不假定平台实时状态。
- 编辑／搭配填写相同组合名，把材料组成一顿或一次出门；日期可空。拖动或卡片菜单移动区域。
- 自由添加默认“食材／可购买”。这是采购可能性，不保证具体门店有货；不自动下单或创建库存。
- 路线手动添加／排序现有地点，直线距离只作参考；逐段打开高德步行／公共交通／驾车／骑行导航，真实路线与耗时由高德计算。
- 无坐标地点仍可打开笔记；多门店券须主动选门店；同名地点不会按名称去重，而按 placeId。
- 已处理仅结束工作卡片；不会改券状态、库存或日记。先放一放可随时拿回。

## 数据

`30_项目/个人生活记录系统/食物工作空间.md` 保存工作卡片与路线，Markdown 可读摘要＋带版本 JSON 标记区块。其他正文保留。原始券、库存、地点、券食安排都只读。口述食品不是正式库存或精确数量；原批次身份不明时不合并。

工作卡 id 是规划卡身份，sourceKey 仍指原 benefitId/entityId/itemId/placeId，不是新实体身份。同一来源可在先放一放／已处理后再次挑选。

写入通过 Vault.process 原子更新，比较完整旧数据，冲突时暂停修改并要求刷新。单次修改保存成功后更新内存；失败不会显示成功。跨设备同步仍需等同步完成，无法取代 Syncthing/LiveSync 的文件级冲突处理。损坏、重复标记、未知版本不覆盖。

本机独立开发，不修改个人地图或券食源码。没有网络接口或密钥；高德导航仅在用户点击时携带选中地点坐标。个人地图按钮通过公开命令打开既有插件。

## 开发

Node 22.20+；`npm ci`、`npm test`、`npm run build`。仅 main.js、manifest.json、styles.css 安装到 Vault `.obsidian/plugins/food-workbench/`。源码与依赖放库外工作树。测试使用通用虚构食品样例；真实库存、工作卡、地点和路线只保存在用户自己的 Vault。

## 当前限制

路线是单个当前草稿，支持多个停靠点，不自动求最优路线，不内嵌道路地图；可随时打开既有个人地图查看。工作台不发布正式券食日程或 Outlook 事件。食品期限字段暂时只读取现有 validTo，不推断保质期。无 OCR、订单导入、库存扣减、通知或完整营养计算。手机提供响应布局和移动菜单，实机触控待验收。
